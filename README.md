# CleanTiming

**クリック後の射撃・命中などの画面変化を画像で追い、設定変更前後の反応を比べるWindows用ツール。**

基準：本ツールのクリック受信を0msに揃え、変化を挟む2枚の画像から反応の観測区間を求めます。

- 観測する変化：弾数減少・反動開始・命中表示・死亡表示など
- 比較するもの：同じ目印の初確認画像、反応までの観測区間、画像更新・取得のばらつき
- 配布版：**1.1.1**／動作確認：**Windows 11 Pro 25H2 x64**

<a id="record"></a>
## ・記録

1. 保存先・取得モニターを選択
2. 開始待ち・記録秒数（または「手動で停止」）・クリック前後の画像範囲を設定
3. 「記録を開始」または**Alt+F6** → 開始待ちの間に対象画面へ切替
4. 調べたいクリック操作を実行 → 設定時間の経過、または「停止」で終了
5. 画像の保存完了後、「QPC画像の解析」を開く

<a id="capture-settings"></a>
### ・記録設定

| 項目 | 設定 |
|---|---|
| 開始待ち／記録時間 | 初期値：10秒／30秒 |
| 画像範囲 | クリック前後各50～500ms（初期値：前後各50ms） |
| 取得頻度 | DXGIの画像更新に追従／上限FPSを指定 |
| 画像形式 | JPEG／PNG（初期値：JPEG・品質75） |
| 保存方式 | メモリー／ストレージ。記録中に画像を確定保存し、一時画像を回収 |
| RAM上限 | メモリー方式の保持画像に適用。ストレージ方式では入力不可・内部予算は独立 |
| 画像記録 | ON／OFF。OFFでも入力と任意のPresent補助を記録 |
| Present補助 | 「公式PresentMonを補助記録」で有効化。対象：開始時の前景プロセス／プロセス一覧／PID指定 |
| 開始キー | Alt+F6／Ctrl+Alt+F6／無効 |
| 軽量設定 | 60fps上限・JPEG品質60・Present補助なし |

- 画像範囲：調べたい反応の前後が収まる範囲
- 軽量設定：画像間隔が広がる分、反応を挟める区間も粗くなる
- 保存先の一時障害：入力は書き込める範囲で継続。画像の欠測を表示し、保存を再試行
- 長い記録：同じフォルダー内で自動分割。解析時に区間を選び、境界の前後画像も確認

<a id="review"></a>
## ・画像と数値の見方・比較

<a id="results"></a>
### ・クリックと画像の対応

| 基準・観測 | 意味 |
|---|---|
| クリック受信＝0ms | 本ツールが入力を受け取った時刻 |
| 画像の「クリックから○ms」 | 画像の更新QPC − クリック受信QPC |
| 変化を初確認した画像 | 反応がすでに現れている側の境界 |
| その直前の画像 | まだ変化が見えない側の境界。コマ送りで内容を確認 |
| 観測区間 | 2枚の境界から求める、クリック受信後の反応の範囲 |

例：**+8ms＝変化なし、+12ms＝初確認 → 反応を挟める範囲は約8～12ms。**

表示区間：入力QPCの±1tickを含め、0.1ms単位で外側へ丸め。上の例はQPC 10MHzの場合、**7.9～12.1ms**表示。直前画像がない場合は上限のみ。

<a id="analysis"></a>
### ・変化を記録する

1. 保存済みの記録フォルダーと対象クリックを選択
2. **A / D**で画像を送り、観測する変化が初めて見える位置を探す
3. 「画面変化開始」（**F**）で指定 → 直前画像も境界として自動採用
4. **Space**で確定 → 次のクリックへ

- 観測する目印：弾数の減少、反動の開始など。同じ目印で繰り返す
- 死亡表示：**G**で別の初確認位置を指定
- 補足：観測対象・比較ラベル・メモ・命中結果、射撃描画や命中表示などの任意マーカー
- 検索・絞り込み：クリック番号／時刻／確認状況

<a id="keys"></a>
#### ・操作キー

| キー・操作 | 動作 |
|---|---|
| A / D | 画像送り（1枚／Shift併用：5枚） |
| Q / E | 前後のクリックへ切替 |
| C | クリック受信直前の画像 |
| F / G | 画面変化／死亡表示の初確認画像を指定 |
| Space | 確定 → 次のクリック |
| X / U | 除外して次へ／除外取消 |
| R / V | 指定解除／次の未確認クリック |
| Z | 画像表示を100%に戻す |
| 画像上のホイール・ドラッグ | 拡大縮小・表示位置の移動 |
| 画像スライダー上のホイール | 画像送り（1枚／Shift併用：5枚） |

画像操作：選択画像のコピー／エクスプローラーでの選択表示

<a id="playback"></a>
#### ・再生

- 再生倍率：**0.0001～4倍**（15段階の選択）
- 再生基準：取得画像／Present提出／OS表示／均等コマ

### ・記録側の遅れを見る

| 表示項目 | 見るもの |
|---|---|
| 直前の画像更新間隔 | その付近をどの細かさで観測できているか |
| 画像更新 → 取得通知 | OS画像更新から、本ツールが画像を受け取るまでの経過 |
| 画像更新 → RAM完了 | OS画像更新から、CPU側への読出し完了までの経過 |
| コピー送信 → Map成功／CPU画素コピー | GPU読出し待ち・CPU側コピーの処理時間 |
| グラフの色 | 同じ記録内の平均・標準偏差に対する相対差 |
| Present提出・OS表示 | 対象プロセスの提出・表示の動き。画像とは独立した時刻系列 |

**反応の区間＝入力受信 → 変化を挟む2枚の画像更新。記録側の遅れ＝画像更新 → 取得・RAM完了。** この2つを分けることで、画面反応の変化と、画像を取り込む側のばらつきを照合できます。

<a id="comparison"></a>
### ・A/B比較

| 比較 | 操作・見るもの |
|---|---|
| 画像 | A・Bの記録を選択 → クリック／マーカーで時刻0を揃え、同じ経過時刻の画像を照合 |
| コマ単位 | 各画像範囲の先頭を基準に、同じ画像番号で照合 |
| 確定結果 | 条件A・Bの観測区間、平均区間、その差を比較 |

- 条件の揃え方：同じ観測目印・画像取得設定・時刻基準
- 確認点：反応の区間がどう変わるか、区間の幅と周辺の画像更新間隔は揃っているか
- 作業の持込み：観測JSONを複数選択して読み込み
- 結果の保存：「比較JSONを保存」

<a id="architecture"></a>
## ・入力と画像の処理順序

![入力受信と画像更新を共通時間軸で対応づける仕組み](architecture.svg?rev=3)

| 段階 | 処理と時刻の意味 |
|---|---|
| Windowsの入力処理 | マウス入力 → ドライバー・HID入力系。本ツールと対象アプリへそれぞれ配信 |
| 本ツールの入力受信 | `WM_INPUT`処理入口でQPCを採時。各クリックの0msに使用 |
| 対象アプリ側 | 入力処理・描画が進み、結果がデスクトップ画像へ現れる |
| OSの画像更新 | `LastPresentTime`に画像更新のQPC。入力と同じ時計で前後関係を整理 |
| 本ツールの取得・読出し | DXGIで取得 → D3D11でコピー → CPU側へ回収。元の画像更新QPCを保持 |
| クリック周辺の保持 | 並行取得中の画像から、クリック前後の設定範囲を保持 |

本ツールと対象アプリの入力処理は別経路です。図の0msは本ツールの受信時刻。画像は取得・保存完了時刻へ置き換えず、**元の更新時刻から「クリックの何ms後か」を求めます。**

割込み・DPC：Windows側の入力処理。本ツールの測定開始は、その後の`WM_INPUT`受信時点。

<a id="troubleshooting"></a>
## ・トラブル対処

| 症状・表示 | 確認するもの |
|---|---|
| 反応が画像範囲に収まらない | クリック後の画像範囲を広げて再記録 |
| 観測区間が広い | 直前画像との間隔、画像更新・取得の記録 |
| 保存画像がない | 画像記録OFF／クリック0件／取得・保存失敗の表示を確認 |
| CT1001 | Windowsの対応版とPCの日付 |
| CT1301 / CT1302 | 空き容量、RAM上限、画像範囲・取得頻度 |
| CT1501 | Present補助の記録。入力・画像の基本記録は継続 |

その他のエラー：画面の「エラー詳細」／ZIP内の`documents/SUPPORT.md`
